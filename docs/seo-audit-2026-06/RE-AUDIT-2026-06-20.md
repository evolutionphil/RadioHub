**Scope:** Full 14-language indexability audit (en, es, fr, de, pt, it, ru, ar, zh, tr, ja, ko, hi, he) across station, genre, region/country/city, homepage, static, and image surfaces. **Headline:** The SSR layer is mature and largely Starter-Guide compliant (unique localized titles/descriptions, one H1 per SSR page type, visible-content-matched structured data, no `meta keywords`, no cloaking, disciplined 410/404/301, correct HTTPS/host normalization). PR #81's `station`/`stations` canonical↔hreflang fix verified correctly deployed, and its image-placeholder guards verified complete. **The dominant remaining theme: PR #81 fixed only two URL segments and the station-detail logo alt — the same class of English-leak persists for every other localized segment and several metadata/alt fields, fragmenting hreflang clusters and weakening localized indexing.**

## Priority 0 — Cluster-breaking / cross-cutting (fixed in follow-up PR)

### A. Localized URL segments de-localize in canonical/hreflang while the sitemap localizes them
Corroborated independently by the hreflang-parity, genres, and regions agents.
`FALLBACK_SEGMENT_TRANSLATIONS` contains only `station`/`stations`. Canonical (`buildLocalizedUrl`) and hreflang (`generateLanguageUrls`) fall back through it; the **sitemap and inbound routing** localize via the full `URL_TRANSLATIONS` table. When the DB `UrlTranslation` collection lacks a row (e.g. `genres`, for which no seed script exists), canonical/hreflang emit raw English `/tr/genres/...` while the sitemap emits localized `/tr/turler/...`. The sitemap-listed URL then canonicalizes to a different URL → Google discards the hreflang cluster ("Duplicate, Google chose different canonical").
- **Affected:** all non-English langs, on genres/regions/country/search and any non-`station` segment.
- **Fix:** add `URL_TRANSLATIONS[lang][segment]` as a static fallback after the DB map (preserving DB precedence) in both `buildLocalizedUrl` and `generateLanguageUrls`, so all four resolvers (canonical, hreflang, sitemap, inbound) converge. Extend the parity test beyond `station`/`stations`.
- **Files:** `lib/seo-shared/src/seo-config.ts` (`generateLanguageUrls` ~1281), `artifacts/api-server/src/seo/url-helpers.ts` (~53), `artifacts/api-server/tests/canonical-hreflang-parity.test.ts`.

### B. x-default reciprocity — non-English pages emit a competing x-default
Flagged by the station-head and hreflang agents. The documented intent is "x-default only from the English page," but the code appends `x-default → hreflangs[0].url` (first allowed language, often not English) on **every** non-English variant. A `de` station page can emit `x-default → /ar/...`. Conflicting x-default across cluster members.
- **Fix:** only emit the `hreflangs[0]` fallback x-default when English is **absent** from the page's allow-list. `seo-config.ts` ~1347-1356.

## Priority 1 — Localized metadata/alt English leaks (fixed in follow-up PR)

### C. Station `<title>` / `og:title` "Listen Live" CTA is English in all 14 languages
`generateLocalizedStationTitle` falls back to literal `'Listen Live'` (DB keys `seo_listen_live_online`/`listen_live` not guaranteed-seeded). The `LOCALIZED_LISTEN_LIVE` map already exists in `seo-renderer.ts` but was never wired into the shared title builder. **Fix:** add a per-language fallback map in `seo-config.ts:generateLocalizedStationTitle`.

### D. Image alt text — grids and flags not localized; alt keys DB-only (USER TOP PRIORITY)
PR #81 localized only the station-**detail** logo alt (and only via DB keys). The **home/genre/region station grids** (`seo-renderer.ts` ~1876/2222/2353) and **country flags** (~2331) use non-localized English alt. The alt translation keys (`seo_station_logo_alt`, `country_flag`) have **no static code fallback** for any language. Sitemap `<image:title>`/`<image:caption>` are hardcoded English across all 14 per-language image sitemaps. **Fix:** static 14-lang fallback registries for logo/flag words; route grid + sitemap alt/caption through them.

### E. Genre-detail `twitter:title`/`twitter:description` are the generic English genres-index copy
The genre branch overrides only `title`/`description`/`keywords`, leaving twitter:* pointing at the English generic. **Fix:** set `twitterTitle`/`twitterDescription` (and og equivalents) from `genreSeo` in `seo-renderer.ts` ~1419.

## Priority 3 — Larger follow-ups (recommended as separate PRs; NOT in this PR)

These need product decisions, data backfill, or larger refactors — documented for sequencing, not applied blindly.

1. **Internal linking / orphan pages (highest organic leverage).** ~80–90% of 56K stations are sitemap-only with near-zero internal in-edges — the in-code root cause of the ~382K "Crawled – currently not indexed" backlog. The `/stations` hub renders zero server-side station links; same-genre/same-city cross-links are hard-disabled; pagination uses `<button>` not `<a href>`; no HTML hub/sitemap page. *Fix:* precomputed neighbor cache to re-enable cross-links + crawlable anchor pagination + an SSR HTML hub index. Big win, multi-step.
2. **Logo coverage (~53.5% of stations emit no image at all).** No enrichment fallback. *Fix:* scrape station `homepage` `og:image`/`<link rel=icon>` into the existing S3 logo processor for `hasLogo:false` stations.
3. **City pages duplicate parent-country title/meta** (city name never injected) + **empty-result country pages stay indexable 200** (incl. diacritic-country mismatches, e.g. slug `turkey` vs DB `Türkiye`). *Fix:* city template branch + re-enable empty-result `noindex` on exact country/city pages + canonicalize country name before the DB query.
4. **`/country/<x>` pages emit no CollectionPage JSON-LD** (only `/regions/<continent>/<country>` does) — structured-data parity gap between the two URL shapes for the same logical page.
5. **Homepage has no per-language title/meta template registry** — English duplication risk on the most important page if any DB key is missing (every other page type has a localized template registry). *Fix:* add `HOME_SEO_TEMPLATES`.
6. **JSON-LD `inLanguage`** sourced from untyped `stationData.language` (often `"english"`/garbage and identical across all 14 variants); **description** falls back to English for non-English pages lacking per-lang AI copy. *Fix:* normalize to BCP-47 / page language; localize the fallback template.
7. **Description-fill backlog** — ~51.8K stations at 1.5s/station with a 5h daily cap = multi-day fill; a station that partially translates then fails mid-batch no longer matches the Phase-1 (zero-desc) filter and can stay permanently partial (those langs are correctly noindexed = safe, but coverage is silently capped). *Fix:* add a Phase-3 sweep re-queuing partial (1–13 lang) stations.
8. **React `genres.tsx` renders zero `<h1>`** (SSR emits one) — client-navigation H1 regression. *Fix:* add `<h1>` mirroring SSR.
9. **robots.txt `Disallow: /search` + SSR `noindex` on `/search` conflict** (Google can't read noindex on a disallowed URL); **`Disallow: /*?`** blocks all query-string URLs. *Fix:* keep one signal; narrow the param block.
10. **Sitemap `changefreq`/`priority`** cargo-culted (Google ignores both) — drop to shrink files; **lower `STATIONS_PER_CHUNK`** (10K) toward the 50 MB hreflang-inflated ceiling headroom.
11. **Organization `sameAs`** uses generic unverified `/megaradio` social handles + **80×80 logo** — verify/replace; `aggregateRating` JSON-LD is the only genuine rich-result (review-star) lever and the `votes`/`averageRating` data already exists (needs on-page review UI + policy compliance).
12. **GSC submission:** submit only the master `https://themegaradio.com/sitemap-index.xml` (non-nested, all 14 langs); the per-language `sitemap-{lang}.xml` files are themselves `<sitemapindex>` documents — submitting those to GSC is the likely cause of the "12 langs show 0 discovered pages" report. Consider removing the 14 per-language `Sitemap:` lines from robots.txt.
